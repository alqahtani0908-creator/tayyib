# طيب — منصة مشروع تعطير مساجد الرياض

منصة ويب متكاملة (عربية، RTL، تعمل على الجوال) لإدارة مشروع تعطير المساجد بين **مدير النظام** و**الجمعيات المشرفة** و**الشركة المنفذة** و**حسابات العرض**.

## المسار (١٢ خطوة)
| # | الإجراء | الجهة |
|---|---|---|
| ١ | إدخال المساجد المختارة (يدويًا أو استيراد Excel) | مدير النظام |
| ٢ | إيعاز المساجد للجمعيات | مدير النظام |
| ٣ | إكمال البيانات الناقصة واعتماد اكتمالها | الجمعية |
| ٤ | التواصل مع الإمام — تقرير القابلية | الجمعية |
| ٥ | دراسة احتياج الجامع — تقرير | الشركة |
| ٦ | اعتماد التركيب | مدير النظام |
| ٧ | التركيب ورفع التقرير | الشركة |
| ٨ | الزيارات الأسبوعية | الجمعية |
| ٩ | قياس الرضا عن الرائحة | الجمعية |
| ١٠ | التقرير الشهري لأداء التعطير | الجمعية |
| ١١ | التعبئة الشهرية + تذكير آلي قبل ٧٢ ساعة | الشركة |
| ١٢ | تقرير التعبئة | الشركة |

قواعد المسار والصلاحيات مفروضة في قاعدة البيانات (RLS + دوال `submit_report`, `assign_mosques`, `complete_data`, `decide_study`)، وليس في الواجهة فقط.

## التقنية
- الواجهة: HTML/CSS/JS بدون إطار، تُجمع بـ `python3 -X utf8 build.py` إلى `docs/index.html` (GitHub Pages).
- الخادم: Supabase (‏Postgres + Auth + Storage حتى ٥٠ ميقابايت للملف + Realtime للإشعارات + pg_cron كل ساعة للتذكيرات).
- المخطط الكامل: `supabase/schema.sql`. اختبار المسار بانتحال الأدوار: `tests/workflow_test.sql`.
- اختبار الواجهة محليًا بعميل وهمي: `python3 -m http.server` ثم افتح `tests/index.html?as=admin` (أو association / company / viewer).

## الحسابات
ينشئ المدير الحساب (بريد + صلاحية + جمعية) فيظهر **رمز تفعيل**؛ يرسله للمستخدم بزر واتساب، فيفتح المنصة ويختار «تفعيل حساب جديد» ويدخل بريده والرمز وكلمة مرور. لنسيان كلمة المرور: «إعادة تعيين الدخول» من صفحة الحسابات.
